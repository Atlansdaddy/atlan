## 2. Fixed tonight — `jsonwebtoken` and the pipeline bug that caused it

`jsonwebtoken` was a **real installed dependency that nothing in Atlan ever ran.**

Where it came from:

1. `scripts/sync-preflight.mjs` vendors `src/lib` + `src/data` wholesale and
   regex-traces every non-relative import into `externalDeps`.
2. That walk includes `lib/probes/v05/fixtures/`. Fixtures are **scan inputs** —
   deliberately vulnerable sample files that exist so a probe can prove its rule
   fires. `JS-AUTH-001/positive.js` and `negative.js` both do
   `import jwt from 'jsonwebtoken'` *as bait*.
3. Line 87 built `installDeps` from **all** of `externalDeps`, not from the
   curated `ENGINE_DEPS` list.
4. The `surprises` check did flag it — but as a `log()` NOTE reading
   "install step will add them; vet if unexpected", **not a gate**. It scrolled
   past during one of the ten sync runs.
5. It landed in `package.json` *and* in `preflight.lock`'s `engineDeps`.

Net effect: the scanner's own vulnerable-code corpus was contaminating the host
project's supply chain — on the same day the supply-chain scanner shipped.

**Fix applied (cause, then symptom):**

- `scripts/sync-preflight.mjs` — added `DEP_EXEMPT_RE = /(^|[\\/])fixtures[\\/]/`
  and a `continue` before dep collection. Fixtures are still vendored (the smoke
  test scans one); their imports no longer count as dependencies.
- `package.json` — `jsonwebtoken` removed.
- `server/src/preflight/preflight.lock` — `engineDeps` corrected to the 3 acorn packages.

Verified after prune: `cockpit-scan.js` imports clean (`PROBES`, `engineInfo`,
`scan`); cockpit answers HTTP 200.

**Open question for tomorrow:** should the `surprises` check *gate* (abort the
sync) instead of just logging? A genuinely new external dep in the engine would
still be installed silently today. Left alone tonight because hard-failing the
sync is a workflow change, not a bug fix.

committed static and correctly has no npm dep.

## 4. The 4 audit findings — all transitive from the Agent SDK

None of them come from anything prunable:

```
@anthropic-ai/claude-agent-sdk
  └── @modelcontextprotocol/sdk
        ├── @hono/node-server   (moderate)
        └── fast-uri            (HIGH)
```

| Severity | Package | Note |
|---|---|---|
| high | `fast-uri` | host confusion via literal backslash authority |
| moderate | `@hono/node-server` | `serve-static` path traversal **on Windows** — not reachable on Android/Linux |
| moderate | `@modelcontextprotocol/sdk` | the chain itself |
| moderate | `@anthropic-ai/claude-agent-sdk` | the chain itself |

**Removing dead deps will not move this number.** It needs an SDK version bump
once upstream ships a fix.

⚠️ **Do not reflexively run `npm audit fix --force`.** The SDK was deliberately
pinned `latest` → `0.3.210` in yesterday's dogfood pass (`539eddc`). A forced fix
would fight that pin and could pull a breaking SDK major.

## 5. Decisions for tomorrow

> **Executed 2026-08-04:** decisions 1 and 3 are done. The four dead deps are
> out of `server/package.json` (vendored browser copies stay — that's the
> chosen model, matching the CodeMirror precedent). The SDK was re-pinned
> deliberately `0.3.210` → `0.3.221`, then `npm audit fix` (not `--force`):
> `npm audit` reports **0 vulnerabilities**. The canUseTool black-box check now
> lives in `test/e2e.mjs` (scout ordered to write a canary file; the file must
> never appear) so every future bump re-proves the finding. Decisions 2 and 4
> remain open.

1. **Remove the four dead deps?** `node-fetch` and `html2canvas` are unambiguous.
   The two `@xterm/*` are dead only because the browser copies are vendored — if
   the intent was ever to source them from `node_modules` instead of committing
   `vendor/`, they should stay and a copy step should be added. Pick one model
   and make it consistent with the CodeMirror precedent.
2. **Should `surprises` gate the sync** rather than log and install? (§2)
3. **Agent SDK bump** — check whether a release past `0.3.210` clears `fast-uri`,
   and re-pin deliberately rather than via `--force`.
4. **Vendoring policy, written down.** The repo now has two vendored trees
   (`web/public/vendor/**` static browser libs, `server/src/preflight/engine/**`
   synced via script). Worth one paragraph in `ARCHITECTURE.md` stating which
   things get vendored, which get npm'd, and why — this whole class of bug comes
   from the boundary being implicit.
